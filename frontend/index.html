系统定位

基于 LLM + RAG 的金融保险营销内容合规审核系统，采用 Rule-First + Workflow 架构。规则引擎做关键词预检，LLM 始终执行完整语义审核，两者结果合并输出。10 步流水线驱动审核，Risk Engine 评分决定三级处置。

约束1：零漏判
一条违规漏过去 = 监管处罚。宁可误报不可漏报，但误报太多人工复核成本爆炸
约束2：法规有隐含逻辑
"禁止+例外"逻辑向量检索无法捕捉，传统RAG只做语义检索会断章取义
约束3：Demo/生产双场景
同一套代码：30秒零配置启动 vs 生产99.9%可用性

10步审核管线

整个审核流程是严格的流水线，每步按固定顺序执行。贯穿案例："买保险就选 XX，稳赚不赔，年化收益 5%！"

① Extract→ ② RuleCheck→ ③ RAG检索→ ④ Rerank→ ⑤ Expand→ ⑥ LLM推理→ ⑦ Format→ ⑧ Validate→ ⑨ CrossCheck→ ⑩ RiskAssess
1信息提取 Extract▶

做什么：从文案中提取关键要素

案例："稳赚不赔"→绝对化声明，"年化收益5%"→收益相关声明，无风险披露

图片输入：自动转JPG+3倍放大→多模态模型提取文字和描述→与文本走相同管线

Demo简化：API Key缺失时降级为关键词提取

2规则预检 Rule Check▶

做什么：关键词库快速预筛查

案例："稳赚不赔"→命中绝对化用语，"年化收益"→命中夸大收益

关键决策：规则命中 ≠ 跳过LLM — 规则命中后结果注入LLM Prompt，告诉LLM"已发现关键词违规，请继续检查更深层问题"

为什么：一段文案可能同时存在关键词违规和语义隐含违规。"未来稳稳的幸福"没触发任何关键词，但保险语境下构成对确定性的暗示

3RAG 检索▶

做什么：文案+关键词拼成查询语句→ChromaDB向量检索Top-20相关法规

技术：HNSW索引 + 余弦距离，嵌入模型 text-embedding-v3（1024维）

生产升级：向量+BM25多路召回+RRF融合+Query Rewriting查询改写

4重排序 Rerank▶

做什么：Top-20→精排Top-5+相邻条文

有Key：qwen3-rerank Cross-Encoder语义精排→Top-5

无Key：降级规则重排（字符重叠+关键词加权）

相邻条文召回：Top-5每条自动召回前后条文，0.7折扣权重。为什么？法规条文不孤立，一条的意思可能依赖上下文定义条款

5条款关联扩展 Expand Relations▶

做什么：沿条款关系图扩展出相关的引用条文

9种关系类型：引用（"依照第X条"）、例外（"除……外"）、补充、定义、冲突、前提、后果、修订、适用

案例：第十九条"调整价格应公告"+但书"费率浮动区间内除外"→不追踪例外=所有调价都判违规

Demo：正则自动提取+49条预标注数据；生产：LLM驱动法规知识图谱

6LLM 深度推理▶

做什么：所有上下文拼装成Prompt→大模型CoT推理→违规类型+条文+推理过程

Prompt拼装：原始文案 + RAG条文 + 关联条文 + 规则预检结果(rule_hint) + Few-Shot案例

模型：qwen3.6-plus（主推理）→ qwen3.6-flash（后备，熔断切换）→ rule-engine（无Key兜底）

选Qwen理由：金融合规数据不出境 + 中文法规语义理解最优

7结构化归一化 Format▶

做什么：LLM推理结果→标准化数据，四件事：

① 归一化：各种格式→标准violations数组

② 规则参考注入：LLM未提规则命中→reasoning前缀[规则引擎参考命中]

③ 降级兜底：LLM失败+规则命中→规则引擎结果；都失败→unknown

④ 数据清洗：compliant→yes/no/unknown，confidence→0~1

8幻觉检测 Validate▶

做什么：LLM可能编造不存在的法规条文→逐条去法规库交叉验证

找到 → 保留

找不到 + 规则引擎有命中 → 降级规则条文，置信度上限0.7

找不到 + 规则也没命中 → 违规降级"未知"，置信度上限0.4

为什么：多级降级策略确保即使LLM幻觉最严重，系统仍给出有依据的审核结论

9交叉复核 CrossCheck▶

做什么：独立轻量模型对审核结论做复核

检查：引用条文与输入内容的语义相关性 + 推理逻辑自洽性

输出：passed / issues / confidence_adjustment(±0.1)

冲突裁决：主模型说违规+复核说合规→保留主模型降低置信度；主模型说合规+复核说违规→降级人工复核

成本效益：成本仅增20%，降低约30%漏判

Demo：API Key缺失时直接跳过

10风险评估 Risk Assess▶

公式：severity×0.5 + article_count×0.1(max0.3) + rule_hit×0.15 + confidence_adj

三级决策：

<0.15 auto_pass · 0.15~0.70 human_review · ≥0.70 auto_block

案例结果："稳赚不赔，年化5%"→风险分1.0，Critical，auto_block。违规：收益承诺+绝对化用语+隐瞒信息+诱导销售

五个关键设计决策
Rule + LLM 协同
规则命中注入Prompt，既保留确定性又发现深层问题。纯规则无法检测语义隐含违规
10步流水线
每步可观测、可调试、可独立优化。端到端出了问题无法定位，无法局部降级
轻量模型CrossCheck
成本仅增20%，降低30%漏判。金融场景一次漏判代价远超20%API费用
条款关系图
"禁止+例外"逻辑向量检索无法捕捉。关系图确保LLM拿到完整法规上下文
Demo/生产分离，接口隔离
四个核心接口换实现不改逻辑。Demo 30秒启动验证核心假设，生产99.9%可用

韧性设计

熔断器
LLM/Embedding独立熔断。连续失败5次→打开→快速失败。半开→试探→成功则恢复
重试机制
可恢复错误（超时、限流）→指数退避+随机抖动。最大重试次数、退避系数可配置
多级降级
向量检索失败→关键词匹配
LLM API失败→规则引擎
重排序失败→规则重排
LLM 降级链
qwen3.6-plus 熔断/超时 → qwen3.6-flash 无Key → rule-engine （永不失败）

质量保障体系

三层质量保障：自动化评估（量化指标） → 人工复核（HITL纠正） → 反馈学习（闭环改善）。不是上线就完事，而是持续度量、持续改进。
📊 自动化评估
CI/CD就绪
标准评估：30个标注用例（合规/违规各半），度量 Precision / Recall / F1 / Accuracy
极限测试：25个边界用例（Prompt注入、角色劫持、XSS/SQL注入、语义隐含违规、边界用例）
指标体系：TP/TN/FP/FN 混淆矩阵 + 平均延迟 + 逐用例通过/失败明细
结果持久化到数据库，支持历史对比 · 可集成 CI Pipeline 自动回归
✋ 人工复核
HITL
触发条件：风险分 0.15~0.70 的审核结果自动进入人工复核队列
复核内容：逐条违规判定 agree/disagree + 修改意见
审计追踪：每次 override 记录 before/after + 修改原因 + 操作人
不是黑箱——每个判定都可追溯、可质疑、可纠正
🔄 评估驱动的持续改进
闭环
评估发现 FP 偏高 → 调整 risk_score 阈值或 Prompt 合规判断标准 → 重新评估验证 → 指标改善
评估发现 FN 偏高 → 扩展关键词库或增加 Few-Shot 样本 → 重新评估验证 → 指标改善
人工 override 数据 → 自动生成 Few-Shot → 下次评估自动体现改善效果
关键设计：评估结果持久化 + 历史对比，每次改动可量化验证，不做盲改
